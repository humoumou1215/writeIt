# Git Diff 渲染准则（M16 抽象规则）

> 定位：这是 git diff「渲染模式」的**顶层判定准则**。所有边界场景裁决都按本文件这几条规则来，不再逐案例反复对齐。
> 它们由 M16 三轮（首轮→02 反馈→05 反馈）的过案例抽象而来；任何新案例先归因到某条准则，命中即按准则处理。

## 总纲

**diff 渲染视图 = 「合并后的可读文档 + 二元增删标注」，正确性优先于最小化标记。**

即：宁可少做/不做"看起来很精"的行内词级，也绝不产生乱码、破坏文档结构、或误导批注连线。

---

## 规则 1：二元化——只红(删) / 只绿(增)，没有黄(改)

任何"修改"一律拆成 **删旧 + 增新** 两种表达，不做独立"修改"态：

- 文本/词级 `A → B`：`` {--A--}{++B++} `` 相邻（红 A 绿 B）。
- mermaid 节点标签变化：同 id 节点 = **旧标签红（划线）+ 新标签绿**；统计并入「删除 N / 新增 N」各 +1。
- 不做「修改了表格单元格」外的第三种颜色。

## 规则 2：语法外壳（marker）永不被标记吞噬

对带块级语法/外壳的行，标记只作用于**内容**，语法外壳保留在标记外，否则文档结构被破坏：

| 语法 | 错误示范 | 正确 |
|---|---|---|
| 列表 `- x` / `1. x` | `{++- 丙++}`（被吞入上行） | `- {++丙++}` |
| 引用 `> x` | `{++> x++}` | `> {++x++}` |
| 标题 `## x` | `{++## x++}`（变文本） | `## {++x++}` |
| 表格行 `\| a \| b \|` | 整行包标记（GFM 吃掉） | 逐单元格标记 |
| 代码栅栏 ` ``` ` | 标记破坏代码块语法 | 栅栏走节点级/整块 |
| 嵌入引用 `![[path]]` | 标记破坏卡片 | 卡片本体不标记 |
| 行内链接 `[t](u)` | 不破坏 `[ ] ( )` | 标记包 `t`/`u` 内容 |

## 规则 3：表格分隔行是「语法行」不是「内容」

`| --- | :---: |` 的变化（几乎都是列宽对齐格式化，`---` 长度随列宽自动拉长）**永不标记、不产批注卡、原样输出新行**——否则 GFM 分隔行识别失效 → 整表退化为普通段落。
表格的业务内容变化（单元格值、行增删）才按单元格标记。

## 规则 4：行内词级 vs 拆两行

修改对按「有无有意义的共同内容」分两种处理：

- **有共同内容**（splitCommon，或字符级 LCS 含 >1 个非空白 ctx 字符）→ **行内多点标记** `` {--A--}{++B++} ``。
  - 行含 markdown 元字符（`* _ \` []`）时**强制字符级 LCS**，多点分割，把语法符号随内容包进原子标记 → 无强调纠缠乱码。
- **无共同内容（纯替换 / 块语义不同）**→ 拆成**旧行红、新行绿两行**，绝不把两种不相关内容拼进同一行（避免 `> 引用` 与 `## 标题` 粘连）。

## 规则 5：mermaid 按「存在性」标注，删除可见且保序保拓扑

只认「只在新 = 新增绿」「只在旧 = 删除红」；删除的必须**加回可见**并**插回原始位置**：

- flowchart：删除节点加回原定义行（含边）。
- state：删除状态加回**定义行 + 相关过渡线**（否则删除状态孤立、边丢失）。
- sequence：删除消息/参与者**按 LCS 对齐顺序插回原位**（先删旧线、再增新线，时序不乱）；participant 增删也标注（绿增/红删 + 删除行加回）。
- 消息/参与者文本用**精确匹配**（避免前缀包含误命中，如「推送客户」≠「推送客户资料」）。

## 规则 6：嵌入引用 = 源文件的分身

- 引用行本身变化：**新增 → 卡片绿色「新增引用」徽标**；**删除 → 缩略红行 1 行**；不做三态黄。
- **当前文件 diff 视图须显示被嵌入源文件在「对比范围」内的改动**（工作区 / 提交范围统一，base 传参）：卡片「内容有改动」角标 + 内嵌源文件改动摘要（仅变化行 + mermaid 概要），效果等同直接打开源文件。

## 规则 7：块级段落要独立，不粘连

纯新增的多行「段落行」之间补空行（Milkdown 单换行=硬换行，避免多段粘连）；列表项/标题/引用等块行不插入破坏性空行。

## 规则 8：批注卡必须可定位（连线正确）

每张批注卡精确连到标注处，锚点由三元唯一确定：

1. **类型**：新增卡只匹配 `diffIns`，删除卡只匹配 `diffDel`（避免同名漂移）。
2. **精确文本**：anchor = 标记的精确查找串（表格行=首个变更单元格值，块级=首行内容，不用整行）。
3. **顺序去重**：多个同值锚点按文档顺序 **used 去重**分配不同位置。

块级特殊卡（新增/移除引用）× 定位到 `file_block` 卡片节点而非文本。

---

## 判定流程（新边界场景怎么裁决）

1. 是语法外壳/结构行（表格分隔行、列表/引用/标题 marker、栅栏、嵌入、链接外壳）？→ 规则 2、3：保留外壳只标内容；分隔行不标。
2. 是"修改"语义？→ 规则 1：拆删+增。
3. 是注释/卡片/mermaid 节点级？→ 规则 5、6。
4. 文本层面：有共同内容 → 行内词级（含元字符走 LCS）；无 → 拆两行 → 规则 4。
5. 是否破坏段落/结构/可读？→ 规则 7 + 总纲：宁可拆开也不粘连、不乱码。
6. 是否有批注卡？→ 规则 8：一定可连线。
